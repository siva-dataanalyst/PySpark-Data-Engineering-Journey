# 🌱 What I Learned Today

Today was not about learning PySpark syntax.

Instead, I learned **why Apache Spark was created** and how Big Data technologies evolved over time.

I understood that every technology exists because the previous solution had limitations.

The learning journey became clear to me:

Single Machine

↓

Distributed Computing

↓

Hadoop

↓

HDFS

↓

MapReduce

↓

Apache Spark

Instead of memorizing definitions, I now understand the purpose behind each technology.

---

# 🧠 How My Thinking Changed

Before today's session, I believed that whenever data became very large, Spark should be the first choice.

Now my thinking has changed.

As a Data Engineer, I should first ask:

- Can SQL solve the problem?
- Can Python or Pandas solve it?
- Can the current solution meet the business deadline?

If the answer is **Yes**, there is no need to introduce Spark.

I realized that choosing the right technology is more important than choosing the newest technology.

---

# 💼 What I Would Do as a Data Engineer

If I join a company and receive a new data processing task, I will not immediately recommend Spark.

Instead, I will:

1. Understand the business problem.
2. Estimate the amount of data.
3. Identify the required processing time (SLA).
4. Evaluate whether existing tools can meet the requirement.
5. Recommend Spark only if distributed processing is genuinely needed.

This is the approach I want to follow in my career.

---

# 🎯 Key Takeaways

Today I learned that:

- Big Data has no fixed size.
- Distributed Computing solves the limitations of a single machine.
- Horizontal Scaling is generally preferred over Vertical Scaling for Big Data.
- Hadoop introduced distributed storage and processing.
- HDFS stores data across multiple machines with replicas.
- MapReduce processes data but performs frequent disk I/O.
- Spark improves performance by reducing unnecessary disk I/O.

The biggest lesson was that **technology should always be selected based on business requirements.**
